# Visual C# 2010 Express + MS SQL Server (Express)

Столкнулся с особенностью Express версии Visual Studio 2010 (наверняка в ранних экпрессах тоже самое) - в качестве источника данных (Data Source) Visual C# Express предлагает на выбор только источники, работающие с файлом, а не с сервером.
Вот так это выглядит:
![](http://s51.radikal.ru/i132/1005/ac/ff5c9cca7ca7.png)
В то же время в Visual Web Developer 2010 Express ( и в VS2005 Pro тоже ) список выглядит так:
![](http://s56.radikal.ru/i153/1005/2f/73096e019d8f.png)
Как видите, список побогаче. Вначале я решил было, что Visual C# переглючило, и стал искать возможность получить список источников данных, аналогичный тому, что есть в Web Developer.
Переустановка ни к чему не привела. Тогда я нашел место, где в реестре хранится этот список для Visual WD Express - это тут
*HKEY\_LOCAL\_MACHINE\SOFTWARE\Microsoft\VWDExpress\10.0\DataSources*. Я его скопировал в *HKEY\_LOCAL\_MACHINE\SOFTWARE\Microsoft\VCSExpress\10.0\DataSources* - для VC#Express. Но это ничего не дало. В ходе экспериментов выяснилось, что похоже список возможных источников данных зашит где-то в самом VC#Express. Откуда такие данные? Очень просто - допустим VC#Express берет все источники из реестра и как-то проверяет что это файловый источник, а не серверный. Тогда берем и перименовываем в реестре GUID одного из файловых источников - я менял {485C80D5-BC85-46db-9E6D-4238A0AD7B6**B**} на {485C80D5-BC85-46db-9E6D-4238A0AD7B6**C**}. Если бы наше допущение было верным - то количество источников не поменялось бы. Но это не так - Microsoft SQL Server Database File исчезает (это его GUID я менял) из списка. Также я пытался копировать ветку реестра с этим GUID - дубликат источника не появлялся.
Кроме того, выяснилось что VC#Express не проверят файловый ли это источник. Как это проверить? Опять же просто - берем GUID серверного Microsoft SQL Server {067EA0D9-BA62-43f7-9106-34930C60C528} и меняем его на GUID Microsoft SQL Server Database File {485C80D5-BC85-46db-9E6D-4238A0AD7B6B} - и, о чудо!, в списке источников данных теперь вместо файлового источника - серверный:
![](http://s05.radikal.ru/i178/1005/cd/ec8b5a50d0e5.png)
Но чуда на самом деле нет. При попытке выбрать этот источник - все равно появляется окно выбора файла с базой даннных:
![](http://s56.radikal.ru/i154/1005/6b/9664394e7d76.png)
а не выбора сервера и базы данных на нем, как должно бы было быть:
![](http://s39.radikal.ru/i083/1005/58/d5a027fb4bc4.png)
К сожалению, в недрах Visual C# 2010 Express мне не удалось найти место, где забита эта логика, так что я оставил попытки что-то тут изменить. Кому не лень копать - дерзайте =)
Позже в интернете я нашел упоминания подобной проблемы у других людей, и оказалось, что это совсем не проблема, а такая "фича" всех компонентов Express версии. То есть типа хотите сервер - покупайте нормальную Visual Studio.
Но есть одно но - "фича" не распространяется на Visual Web Developer 2010 Express - в нем то все нормально с подключением к серверам. И это как говорится "доставляет". А почему - расскажу ниже.
Итак, что у нас в результате. У нас есть VC#Express, на котором мы хотим писать Windows приложение, которое должно подключаться к MS SQL Server. Но есть проблемка - как Data Source невозможно выбрать MS SQ Server, а значит нельзя, например, перетаскивать таблицы в дизайнер того же Linq2SQL (с Entity Framework я думаю тоже самое). Что делать?
На самом деле все зависит от того чо вы хотите и как вы хотите.
Случай 1. Вам вообще не нужен этот визуальный дизайнер. Дело в том, что например тот же DataContext из Linq2SQL спокойно коннектиться к серверу - нужно только правильно указать ConnectionString. Например, так:
> `const string ConnectionString = @"Data source=.\SQLEXPRESS;Integrated Security=SSPI;Database=NorthWind";
> // Use a connection string.
> DataContext db = new DataContext(ConnectionString);
> * This source code was highlighted with Source Code Highlighter.`

При этом надо ручками создать классы сущностей, лежащих в нужных таблицах, присвоить сущностям и их свойствам нужные аттрибуты, чтобы Linq2SQL правильно все это дело мапил на базу данных, и в принципе можно работать. Минусы - никакой "визуальщины" и много ручной работы.
Случай 2. Избавимся от ручной работы. Я имею в виду ручное создание классов для сущностей лежащих в базе. Для этого есть замечательная утилитка **sqlmetal.exe**. Как ей пользоаться есть в MSDN. Смысл в том что мы ей скармливаем имя сервера, имя базы данных и имя файла и на выходе в этом файле имеем классы для всех сущностей нужной БД. Так, например, вызвав в консоли
*"c:\Program Files\Microsoft SDKs\Windows\v7.0A\bin\SqlMetal.exe" /server:.\sqlexpress /language:csharp /pluralize /database:northwind /code:northwind.cs* 
получим файлик northwind.cs с нужными классами, который можно подключить к нашему проекту в VC#Express.
От рутины избавились, но визуальности так и нет.
Способ 3. Вспоминаем про Visual Web Developer. Идея простая - создаем в нем Class Library, подключаемся там к нужному DataSource, добавляем Linq2SQL (or EF), перетаскиваем таблички, настраиваем свойства "мышкой" и так далее. А дальше либо добавлем эту библиоеку как Reference к нашему проекту в VC#Express, либо даже добавляем сам проект к нашему Solution. Естественно, добавлять новые таблички перетаскиванеим из Database Explorer в Linq2SQL дизайнер не получится - ибо БД нашей в Database Explorer нет - для этого придется открывать Web Developer. В принципе ничего страшного нет - ну открываем мы еще один иструмент. Но допустим кому-то и этого не хочется. Тогда...
Способ 4. От Web Developer нам не избавиться, конечно, но все его функции теперь сведутся к тому, чтобы добавить нужный DataSource в список Database Explorer - открываем WD, открываем в нем Database Explorer, добавляем новый источник MS SQL Server, указываем имя сервера и БД - все получаем нужный источник в Database Explorer. Теперь обязательно нужно закрыть WD. далее берем файл
*%appdata%\Microsoft\VWDExpress\10.0\ServerExplorer\DefaultView.SEView*
и копируем его в
*%appdata%\Microsoft\VCSExpress\10.0\ServerExplorer\DefaultView.SEView*.
В итоге если открыть VC#Express в Database Explorer, у нас будут все те источники данных, что были в Web Developer. Теперь можно точно также добавлять таблички в Linq2SQL дизайнер, например, перетаскивая их из соответсвующих баз данных. Нирвана почти достигнута. Как заключительный штрих предлагаю вместо копирования DefaultView.SEView сделать на него символическую или жесткую ссылку. Для этих целей рекомендую [Link Shell Extension](http://schinagl.priv.at/nt/hardlinkshellext/hardlinkshellext.html).
