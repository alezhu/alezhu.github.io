# Как DrWeb мешает установке обновлений безопасности.

В прошлый вторник (10.04.2012) Microsoft выпустила пучок обновлений. Почти все они скачались и поставились, а пара из них выдала сообщение, что не может. Вот они:

1. Обновление для Microsoft Outlook 2010 (KB2553248) 32-разрядный выпуск
2. Обновление безопасности для Microsoft Office 2010 (KB2598039) 32-разрядный выпуск

Особо не придавая этому значения, я в течении недели периодически нажимал кнопку Повторить обновление, но с тем же результатом. Сегодня решил разобраться в чем же проблем.
Итак, Google пока не знает почему эти обновления могут не ставиться. Microsoft приводит стандартные отмазки типа - почистите диск, обратитесь к администратору и тыпы. Сами обновления никакой путной ошибки не выдают.
Лезем в Администрирование - Просмотр событий и видим там два более подробных сообщения:

1. Продукт: Microsoft Office Professional Plus 2010 -- Ошибка 1406.Не удается записать значение DisableExceptionChainValidation в раздел реестра \SOFTWARE\Microsoft\Windows NT\CurrentVersion\Image File Execution Options\outlook.exe. Убедитесь, что у вас есть необходимые разрешения на доступ к реестру, или обратитесь в службу поддержки Майкрософт (PSS). Сведения о том, как обратиться в службу поддержки, см. вPSS10R.CHM.
2. Продукт: Microsoft Office Professional Plus 2010 -- Ошибка 1406.Не удается записать значение DisableExceptionChainValidation в раздел реестра \SOFTWARE\Microsoft\Windows NT\CurrentVersion\Image File Execution Options\dw20.exe. Убедитесь, что у вас есть необходимые разрешения на доступ к реестру, или обратитесь в службу поддержки Майкрософт (PSS). Сведения о том, как обратиться в службу поддержки, см. вPSS10R.CHM.

Похоже что-то не то у нас разделом реестра. Открываем реестр через Regedit, топаем в ветку, например, HKEY\_LOCAL\_MACHINE\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Image File Execution Options\dw20.exe и пытаемся поменять этот DisableExceptionChainValidation на что нибудь. Ошибка - нет прав. Идем в разрешения этого ключа реестра, пытаемся что-то менять - нет доступа. Хотя тут же видно что права то все есть!
Гуглим. По этой ссылке http://otvety.google.ru/otvety/thread?tid=31dd8b0fa46f6229&pli=1 у человека похожая проблема и решение "Установленный DrWeb не давал прав! Его нужно убить (например, из процессов) и всё будет!".
Проблема в том что DrWeb убить себя никак не дает. Ок. Отключаем его самозащиту - пофиг. Отключаем все его сервисы - пофиг. Вспоминаем, что в его настройках есть какая-то галка "Запрещать модификацию важных объектов Windows", снимаем ее - пофиг.
Перезагружатьяс чтобы отключать защиту, как я писал тут когда то http://az-spb-ru.livejournal.com/22189.html было лень. Поэтому полез на форум DrWeb может там кто-то что-то спрашивал похожее. И точно! Вот в этой ветке форума http://forum.drweb.com/index.php?showtopic=287541 есть ответ. Оказывается в реестре можно прописать пути к ключам и отдельным значениям реестра, которые DrWeb будет запрещать менять. Прописываются они тут HKEY\_LOCAL\_MACHINE\SYSTEM\CurrentControlSet\Services\DwProt\Parameters\Keys. И похоже защита DrWeb имеет глюк, потому что там нет записей для \Image File Execution Options\outlook.exe и для Image File Execution Options\dw20.exe и теоретически защита на них не действует. Но там есть записи для собственных сервисов DrWeb, например, \REGISTRY\MACHINE\SOFTWARE\MICROSOFT\WINDOWS NT\CURRENTVERSION\Image File Execution Options\frwl\_svc.exe. И похоже, DrWeb заодно не дает менять как сам родительский ключ Image File Execution Options, так и все что в нем.
Исправим это (делать все с отключенной самозащитой DrWeb).
Первым делом сохраняем резервную копию ветки с ключами HKEY\_LOCAL\_MACHINE\SYSTEM\CurrentControlSet\Services\DwProt\Parameters\Keys через экспорт ее в файл.
Потом удаляем весь ключ HKEY\_LOCAL\_MACHINE\SYSTEM\CurrentControlSet\Services\DwProt\Parameters\Keys со всем содержимым.
Идем опять в HKEY\_LOCAL\_MACHINE\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Image File Execution Options\dw20.exe и пытаемся поменять этот DisableExceptionChainValidation на что-нибудь - Ура! Работает! Виновник найден.
Ставим обновления. Импортируем обратно сохраненные ключи. Включаем самозащиту DrWeb и отключенные сервисы. Profit!
