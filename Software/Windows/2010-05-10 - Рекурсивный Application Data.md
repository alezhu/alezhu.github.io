# Рекурсивный Application Data

В Vista компания Microsoft "перекроила" ссылки на пользовательские данные. Если раньше все лежало в Documents and Settings, то теперь все не совсем так. Например, вместо Documents and Settings используется Users, а первый сделан как символическая ссылка на второй. А вот Documents and Settings\All Users лежит в ProgramData прямо в корне системного диска.
При этом чтобы не нарушить работу старых приложений, которые про новую моду ничего не знают, сделана куча символических ссылок со старых "мест работы" на новые. И в частности есть рекурсивные ссылки, то есть такие ссылки, которые лежат внутри какого-либо каталога и ссылаются на него же. Далеко ходить не надо - ProgramData\Application Data ссылается на сам ProgramData.
Таким образом, хотя, например, данные приложений Microsoft для всех пользователей лежат фактически в ProgramData\Microsoft\\* старое приложение будет их искать по пути Documents & Settings\All users\Application Data\Microsoft\\*. Но благодаря тому что, D&S ссылается на Users, а Users\All users ссылается на ProgramData, а ProgramData\Application Data ссылается на сам ProgramData - мы попадем туда где фактичеки данные и лежат.
С такими ссылками возникает проблема при поиске. То есть приложение (например, Total Commander), которое что-то ищет в Users и его подпапках попадает на Application Data, не разбирает, что это ссылка ведущая как бы назад, и снова начинает в ней искать - хотя поиск там уже был. И в итоге получается мы залезаем в вот такие вот дебри:
c:\Users\All Users\Application Data\Application Data\Application Data\Application Data\Application Data\Application Data\Application Data\Application Data\Application Data\Application Data\Application Data\....
Как с этим бороться? Если стоит Windows 7 и она поставлена с "нуля", то там похоже и так все уже сделано. Если же стоит Vista или Windows 7 ставилась как обновление на Vista, то делаем следующее:
1. Открываем Свойства **c:\Users\All Users\Application Data\**.
2. На вкладе Безопасность тыкаем кнопку Дополнительно
3. Во всплывшем окне тыкаем кнопку Изменить разрешения
4. Тыкаем кнопку Добавить.
5. Пишем "Все" (в английской винде - наверное, All). Тыкаем ОК
6. Выбираем Только для этой папки
7. Ставим галку в столбике Запретить напротив пункта "Содержание папки / чтение данных".
8. Тыкаем кнопки OK пока не закроем окно Свойства.
Наслаждаемся - Total Commander в эту папку входить не будет.
В тоже время работа с подпапками внутри Application Data не нарушается.
Наример, если создать в c:\Users\All Users\Temp файл 1.txt и потом в том же Total Commander написать
`copy "c:\Users\All Users\Application Data\TEMP\1.txt" 2222.txt`
То получим копию этого файла с именем 2222.txt. (Заметьте обращение шло через Application Data).
Также, если запустить cmd.exe и написать `cd "c:\Users\All Users\Application Data"`, то в строке приветствия в cmd.exe мы увидим, что текущий каталог изменился на Application Data. Можно опять написать cd "Application Data" и мы войдем еще глубже в иерархию, но команда dir уже, например, не даст никаких результатов. То есть, установленный нами запрет дает возможность указывать Application Data внутри другого пути, но читать содержимое папки, на которую указывает Application Data, невозможно.
