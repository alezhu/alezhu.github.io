Запуск скриптов PowerShell с параметрами

Запуск скриптов PowerShell с параметрами Решил я тут небольшой скриптец написать на PowerShell. Не хотелось завязываться на установку всякой внешней лабуды типа перлов с питонами, а PS сейчас в каждой винде. Особо то я его ен знаю. Ну все-таки написал как-то, не суть. Скрипт на вход должен получать путь к каталогу, а если того нет, то работать с текущим. В конце встал вопрос “а как его запускать?”. По умолчанию в винде типа с целью безопасности запуск PS-скриптов не работает. При том же даблклике он открывается в редакторе. Чтобы его запустить надо в контекстном меню выбрать нужный пункт. Естественно это лишний геморрой и аргумент в такой запуск не подставишь. Можно, конечно, писать “powershell.exe bla bla bla”, но нафиг совершать лишние никому ненужные действия и снижать ресурс клавиатуры =)? Короче. В Реестре по пути HKEY_LOCAL_MACHINE\SOFTWARE\Classes\Microsoft.PowerShellScript.1\Shell\ есть несколько подразделов. По умолчанию там должны быть 0, Edit и Open. В самом Shell значением по умолчанию стоит Open. А вот для запуска используется ничем не примечательный 0. Поэтому первым делом в Shell в значение по умолчанию вместо Open пишем 0. После этого ps1-файлы будут запускаться по даблклику или по имени в консоли/Far/TC. Но остается проблема с аргументами - они в скрипт не передаются. Смотрим что напиисано в значении по умолчанию по пути HKEY_LOCAL_MACHINE\SOFTWARE\Classes\Microsoft.PowerShellScript.1\Shell\0\Command. Вообще в разных виндах там может быть разное. В Windows 7 там, например, стоит “C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe” “-file” “%1” . А в Windows 10 - “C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe” “-Command” “if((Get-ExecutionPolicy ) -ne ‘AllSigned’) { Set-ExecutionPolicy -Scope Process Bypass }; & ‘%1’” (именно так с кавычками) Но смысл в любом случае в том, что передается только 1й аргумент (%1) - в данном случае это имя самого ps1-файла передается в powershell.exe. Соответственно, после %1 дописываем %* - что означает все аргументы. Для Win10 должно стать в итоге “C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe” “-Command” “if((Get-ExecutionPolicy ) -ne ‘AllSigned’) { Set-ExecutionPolicy -Scope Process Bypass }; & ‘%1’ ‘%*’ " Причем для меня пока осталось непонятным, что в скрипт вроде как при таком написании должны передаваться все изначальные аргументы - то есть имя самого скрипта первым. Но этого не происходит. То есть при запуске script.ps1 test - в $args[0] будет именно test, как мы ожидаем при нормальном запуске.

Там есть поиск по названию или номеру поста, но… Пользоваться этим мне все равно было не очень удобно. Поэтому я написал расширение для Opera. Расширение может работать в двух режимах. По умолчанию на странице с информацией, что автор переместил топик в черновики, генерируется текст и ссылка, которая ведет на http://savepearlharbor.com/ на конкретный этот сохраненный пост. Вы увидите скромную одну галочку, которую нужно поставить (выглядит вот так): Если заинтересовались, еще раз ссылка на расширение. Если кто-то захочет доработать или адаптировать для Chrome/Firefox, ну, или по другим причинам, то вот ссылка на исходники. Поскольку дизайнер из меня никудышный, то причесать вид настроек расширения я даже и не пытался. Если кто-то захочет что-то предложить в этом плане - тоже welcome!

Отладка Browser Helper Object

Отладка Browser Helper Object Browser Helper Object (aka BHO) – это фактически плагин к Internet Explorer (и просто Explorer). Ну, собственно, если вы это читаете, значит скорее всего пришли из поисковика по фразе в заголовке. И, следовательно, в курсе что это и как их писать. А раз вы их пишете то рано или поздно столкнетесь с необходимостью их отладки в Visual Studio (скорее всего и в других IDE, например Delphi, проверять лень). Отлаживать Dll-ки в принципе можно двумя путями – аттачиться к уже запущенному процессу или указать, что нужно запустить при запуске отладки. С аттачем наверное разберетесь, а вот если указать в качестве запускаемого приложения iexplore.exe, то начиная с Internet Explorer 8 будут проблемы – точки остановки просто не включаются и не срабатывают. Происходит это потому, что IE8 и старше по умолчанию запускает свои вкладки в отдельных процессах. “Студия” аттачится к первому процессу IE, а он BHO не грузит, а грузят их запускаемые им процессы-вкладки, но к ним студия уже не коннектится. К счастью, можно заставить IE не создавать отдельных процессов, а все вкладки создавать в одном. Делается это очень просто в реестре в ветке HKCU\Software\Microsoft\Internet Explorer\Main создаем ключ TabProcGrowth типа DWORD и присваиваем ему значение 0. После этого точки останова будут срабатывать. Happy Debug. ...
