Создание расширений для Opera

Создание расширений для Opera Решил создать расширение для Opera для добавления ссылок на веб-страницы в сервисе Delicious. Вернее решил доработать существующее существующее by shwetankdixit, потому что оно работало не совсем так, как я привык. Под “привык” я имею в виду стандартный ссылку-скрипт, которая доступна на сайте Delicious. В частности существующее расширение не устраивало следующим: Оно открывало новую вкладку Оно выводило версию формы для создания закладки на сайт без опций и списка тегов Оно не копировало выделенный на сайте текст в заметки к закладке Мое расширение действует как раз наоборот - открывает форму созданий закладки в той же вкладке, где сейчас открыт добавляемый в закладки сайт, форму выводит со списком тегов и копирует выделенный текст с сайта в заметки. Вообще расширение получилось очень простое - можете убедиться поставив Delicious Extension by AZ и посмотрев потом в исходники. Так, с рекламой закончили. Вообще идея поста была не столько попиарить расширение, сколько рассказать о некоторых тонкостях создания расширений для Opera. Никаких особых секретов я, конечно, не открою. Enterprise Library Custom Logger

Enterprise Library Custom Logger Изучаю тут помаленьку Enterprise Library. Книжку читаю по нему и экспериментирую. Книжка, кстати, так себе - могла бы быть и поглубже. Но речь не о ней. Итак, в Enterprise Library есть модуль логирования. Работает примерно так. В своем приложении вы получаете экземпляр “Писателя в лог” (LogWriter) и вызываете у него одну из перегрузок из метода Write: `1. LogWriter writer = EnterpriseLibraryContainer.Current.GetInstance(); 2. writer.Write(…); This source code was highlighted with Source Code Highlighter.` “Писатель” берет из настроек приложения указанного “читателя” (или “слушателя” - потому, что классы имею в названии Listener) и передает ему запись типа LogEntry. “Слушатель” преобразует запись LogEntry с использованием заданного в настройках приложения.. “форматировщика” (класс, который реализует интерфейс ILogFormatter) и выводит полученное куда-нибудь (это зависит от типа “слушателя” - в файл, в базу данных, в журнал событий Windows и т.д.). Так вот, решил я воспользоваться этой функциональностью, чтобы просто выводить сообщения в консоль. Причем выводить только само сообщение. Как такое можно сделать? 1й вариант в качестве слушателя назначить System Diagnostics Trace Listener (класс SystemDiagnosticsTraceListenerData). При этом в качестве TraceListener ему назначить класс System.Diagnostics.ConsoleTraceListener. Все работает, но вместо простого сообщения выводится полная информация по сообщению - время создания, категория, имя машины и пользователя и так далее - короче все поля класса LogEntry. И при этом гадость в том, что для System Diagnostics Trace Listener нельзя назначить “форматировщика”. Тогда 2ой вариант - пишем собственного слушателя. Наследуем его от CustomTraceListener. Skype не сворачивается в трей в Windows 7

Skype не сворачивается в трей в Windows 7 Не так давно разработчики Skype выпустили обновление своего продукта. Вернее было даже два обновления с небольшим перерывом. Версии первого я, к сожалению, не помню, а второе - 4.2.0155. Но началось все с первого. А началось следующее - в Windows 7 Skype при закрытии своего главного окна не убирал кнопку с панели задач. Причем в других версиях Windows - все работало как и раньше. Официальный форум на сайте Skype запестрел сообщениями об этом баге. На что разработчики ответили, что это не баг, а фича. Не знаю точно чем они руководствовались, но судя по всему такое поведение создано в угоду тому как Windows 7 по умолчанию показывает приложения на панели задач, а именно большими кнопками без подписей типа так: ![[bigbutton.png]] Таким образом, винда показывает, что приложение запущено, а по правой кнопке, например, можно менять свой статус в Skype - то есть некий аналог трея. Но многим, в том числе и мне, это похоже не нужно. Более того, я, например, панель задач в Windows 7 привожу в стандартному виду, типа так: ![[taskbar.png]] И мне эта кнопка маячащего в бэкграунде Skype’а, естественно нафиг не нужна. Так вот, поскольку разработчики не изъявили желания исправлять эту багофичу, народ стал искать пути решения. И нашел. Оказалось что, если поставить в свойствах Skype запускаться в режиме совместимости с Windows Vista или XP - то он начинает работать как и положено. Но тут разрабы выпускают новую версию и все - эта фишка с совместимостью перестает работать. Короче, мне это не понравилось и я наваял патч, который заставляет Skype версии 4.2.0.155 под Windows 7 при закрытии сворачиваться в трей (вернее убирать свою кнопку с панели задач - в трее он и так все время есть). ВНИМАНИЕ! Сразу хочу предупредить - в Skype встроена проверка на изменения его файла, поэтому в данном случае ее пришлось отключить, поскольку при пропатчивании файл меняется. Также никакого подробного тестирования не проводилось - вроде все работает, но кто знает что там могло сломаться. Поэтому никаких гарантий не даю и никаких претензий предъявлять не надо - все делаете на свой страх и риск. Качаете тут http://www.box.net/shared/ffdxhpax7v ZIP-файл, распаковываете его в папку со Skype, запускаете распакованный exe, тыкаете Apply patch. На выходе имеем пропатченный skype.exe и изначальный непатченный вариант в skype.bak. Если что пойдет не так - вторым перезапишите первый. UPDATE Для версии 4.2.0.158 - http://www.box.net/shared/ktqutbd7no Для версии 4.2.32.155 - http://www.box.net/shared/r5p23gskyd Для версии 4.2.32.158 - http://www.box.net/shared/33f0eyy0tl UPDATE 2 В версии 4.2.x.166 в настройках появилась соответствующая галочка. Патч больше не нужен. Обновляйте версию.

Проблемы с Центром устройств Windows Mobile

Проблемы с Центром устройств Windows Mobile Дошли руки до синхронизации моего PocketPC с новой Windows 7 и тут вылезла новая ботва - не запускается Центр устройств Windows Mobile. Выдает окно типа “У Вас должна быть установлена следующая версия .Net Framework 4.20506… бла бла бла”. Самое интересное, что именно эта версия и установлена - вместе с Visual Studio 2010 поставилась. Ладно попробовал я переставить 4й framework - не ставится. Пообщался с “мировым разумом” - тот про такую проблему пока не знает. Запустил тогда Sysinternals Process Monitor и пошел смотреть почему этот центр не находит .Net 4, хотя тот стоит. Обнаружил, что на самом деле папку c 4.20506 он находит, но спотыкается на файле mscorwks.dll, которого там нет. Зато есть такой файл например в .Net Framework 2. Видать в Microsoft этот файл для 4 framework’a не нужен - или переименовали, или распихали по другим dll. Судя по логам Process Monitor, также похоже, что при запуске Центр устройств (или ядро .Net ?) просматривает список установленых дотнетовских фрейморков и юзает последний. При этом видно также, что он пытается открыть файл wmdc.exe.config, которого нет. В этом конфиге в частности можно прописать какой framework использовать. Родилась идея заставить Центр устройств принудительно использовать 2ой framework. Поскольку что там надо в .config писать я естественно не помнил наизусть, я нашел готовый конфиг от C#-кого компилятора по адресу c:\Windows\Microsoft.NET\Framework\v2.0.50727\csc.exe.config, скопировал его в c:\Windows\WindowsMobile\ и переименовал в wmdc.exe.config. И вуаля! Все заработало. ...
