Установка заканчивалась ошибкой “ERROR:The installer has encountered an unexpected error installing this package. This may indicate a problem with this package. The error code is 2908.” Судя по логам, из-за того, что не ставился .Net Framework 4 Beta 1. Попытка отдельно установить последний также заканчивалась неудачей. К сожалению сейчас я уже точно не вспомню те ошибки, что выдавал инсталлятор, но судя по истории поиска Google там присутствовали ошибки с кодами 0x80240017, 0x8002802F и 0x80070643. Копание в логах установки наводило на мысль, что не ставятся обновления Windows6.0-KB956250-v6001-x86.msu и Windows6.1-KB958488-v6001-x86.msu, которые пытается доустановить инсталлятор фреймворка. Их ручная установка также не удавалась. В общем в ходе копания в инсталляторах этих обновлений и логических “умозаГлючений” появилась мысль что в билде 7201 они нафиг не нужны (*). Поэтому родилась мысль заставить инсталлятор .Net Framework 4 пропускать их установку. После чего из пары файлов были выкинуты упоминания об этих обновлениях и установка прошла как по маслу. Итак, в Enterprise Library есть модуль логирования. Работает примерно так. В своем приложении вы получаете экземпляр “Писателя в лог” (LogWriter) и вызываете у него одну из перегрузок из метода Write: `1. LogWriter writer = EnterpriseLibraryContainer.Current.GetInstance(); 2. writer.Write(…); This source code was highlighted with Source Code Highlighter.` “Писатель” берет из настроек приложения указанного “читателя” (или “слушателя” - потому, что классы имею в названии Listener) и передает ему запись типа LogEntry. “Слушатель” преобразует запись LogEntry с использованием заданного в настройках приложения.. “форматировщика” (класс, который реализует интерфейс ILogFormatter) и выводит полученное куда-нибудь (это зависит от типа “слушателя” - в файл, в базу данных, в журнал событий Windows и т.д.). Так вот, решил я воспользоваться этой функциональностью, чтобы просто выводить сообщения в консоль. Причем выводить только само сообщение. Как такое можно сделать? 1й вариант в качестве слушателя назначить System Diagnostics Trace Listener (класс SystemDiagnosticsTraceListenerData). При этом в качестве TraceListener ему назначить класс System.Diagnostics.ConsoleTraceListener. Все работает, но вместо простого сообщения выводится полная информация по сообщению - время создания, категория, имя машины и пользователя и так далее - короче все поля класса LogEntry.
