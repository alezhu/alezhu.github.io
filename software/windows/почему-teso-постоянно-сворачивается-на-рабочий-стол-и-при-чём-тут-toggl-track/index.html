Почему TESO постоянно сворачивается на рабочий стол и при чём тут Toggl Track#

17 ноября 2026 г.

Запускаю The Elder Scrolls Online (TESO). Игра стартует, появляется заставка, проходит буквально 4–5 секунд — и бац, игра молча сворачивается на рабочий стол.

Разворачиваю окно игры обратно из панели задач. Проходит пара секунд — игра снова сворачивается. И так по кругу до бесконечности. При этом сам процесс eso64.exe не завершается, никаких ошибок не выдаёт, просто система упорно выпихивает окно игры на второй план, как будто какое-то невидимое приложение настойчиво забирает фокус ввода на себя.

Классическая ситуация из разряда «полтергейст в Windows». Знакомо? Давайте разберёмся, как поймать невидимого виновника за руку с помощью PowerShell и WinAPI, почему так произошло и как это исправить.

Кто ворует фокус: пишем детектор на PowerShell#

Первая мысль при подобном поведении — какой-то фоновый процесс перехватывает фокус:

  • Оверлеи (GeForce Experience, Discord, Steam);
  • Переключатели раскладки клавиатуры;
  • Обновлялки, утилиты синхронизации или антивирусы.

Но гадать и по очереди выгружать десятки фоновых программ — долго и неэффективно. Гораздо проще и надежнее спросить у самой Windows: какое окно становится активным (Foreground Window) ровно в тот момент, когда игра сворачивается?

Для этого пишем небольшой PowerShell-скрипт с вызовом функций WinAPI GetForegroundWindow, GetWindowThreadProcessId и GetWindowText. Чтобы не сидеть и не ждать у моря погоды, скрипт сам восстанавливает окно игры через ShowWindow(SW_RESTORE) и запускает мониторинг изменений активного окна каждые 50 миллисекунд:

Add-Type @"
using System;
using System.Text;
using System.Threading;
using System.Diagnostics;
using System.Collections.Generic;
using System.Runtime.InteropServices;

public class FocusStealDetector {
    [DllImport("user32.dll")] public static extern IntPtr GetForegroundWindow();
    [DllImport("user32.dll")] public static extern uint GetWindowThreadProcessId(IntPtr hWnd, out uint lpdwProcessId);
    [DllImport("user32.dll", CharSet = CharSet.Auto)] public static extern int GetWindowText(IntPtr hWnd, StringBuilder lpString, int nMaxCount);
    [DllImport("user32.dll", CharSet = CharSet.Auto)] public static extern int GetClassName(IntPtr hWnd, StringBuilder lpClassName, int nMaxCount);
    [DllImport("user32.dll")] public static extern bool ShowWindow(IntPtr hWnd, int nCmdShow);
    [DllImport("user32.dll")] public static extern bool SetForegroundWindow(IntPtr hWnd);

    public static void Monitor(IntPtr targetHwnd, int durationSeconds) {
        // Восстанавливаем окно целевого приложения
        ShowWindow(targetHwnd, 9); // SW_RESTORE
        SetForegroundWindow(targetHwnd);

        IntPtr prevHwnd = IntPtr.Zero;
        DateTime end = DateTime.Now.AddSeconds(durationSeconds);

        while (DateTime.Now < end) {
            IntPtr fg = GetForegroundWindow();
            if (fg != prevHwnd && fg != IntPtr.Zero) {
                prevHwnd = fg;
                uint pid = 0;
                GetWindowThreadProcessId(fg, out pid);
                string procName = "unknown";
                try {
                    using (var p = Process.GetProcessById((int)pid)) { procName = p.ProcessName; }
                } catch {}

                StringBuilder sbText = new StringBuilder(256);
                GetWindowText(fg, sbText, 256);
                StringBuilder sbClass = new StringBuilder(256);
                GetClassName(fg, sbClass, 256);

                Console.WriteLine(string.Format("[{0:HH:mm:ss.fff}] PID={1,-5} ({2,-15}) Class='{3}' Title='{4}'",
                    DateTime.Now, pid, procName, sbClass.ToString(), sbText.ToString()));
            }
            Thread.Sleep(50);
        }
    }
}
"@

# Находим HWND главного окна игры и запускаем слежку на 10 секунд
$esoHwnd = (Get-Process eso64).MainWindowHandle
[FocusStealDetector]::Monitor($esoHwnd, 10)

Запускаем и смотрим на вывод:

[16:04:07.901] PID=28056 (eso64          ) Class='EsoClientWndClass' Title='Elder Scrolls Online'
[16:04:13.349] PID=5860  (TogglTrack     ) Class='HwndWrapper[TogglTrack;;eb931538-599b-42f9-836a-b03799d15616]' Title='Toggl Track'

Повторяем тест ещё раз:

[16:04:31.020] PID=28056 (eso64          ) Class='EsoClientWndClass' Title='Elder Scrolls Online'
[16:04:35.659] PID=5860  (TogglTrack     ) Class='HwndWrapper[TogglTrack;;eb931538-599b-42f9-836a-b03799d15616]' Title='Toggl Track'

Картина стабильная с точностью до секунды: ровно через 4.6–5.4 секунды после активации окна TESO фокус на себя перетягивает Toggl Track (TogglTrack.exe)!

В чём причина: невидимое окно и античит#

Toggl Track — обычный настольный трекер времени для учёта задач. Казалось бы, он тихо сидит себе в системном трее возле часов и никого не трогает. Какое ему дело до онлайн-игры?

Смотрим на свойства окна Toggl Track, которое перехватывает фокус:

  • Класс окна: HwndWrapper[TogglTrack;;...] — стандартный корневой контейнер окна на базе WPF (.NET);
  • Размер и координаты: Left=0, Top=0, Right=0, Bottom=0;
  • Видимость (IsWindowVisible): False!

То есть это невидимое техническое окно нулевого размера! Вот почему на экране визуально ничего не всплывало, а происходило просто сворачивание игры на рабочий стол (или переключение на окно, которое находилось под игрой).

Но почему Toggl Track вообще просыпается и дёргает фокус? Лезем в логи приложения:

%LOCALAPPDATA%\Toggl Track\<ID_пользователя>\logs\logYYYYMMDD.txt

И находим там записи с точностью до миллисекунды:

16:04:07.901 INF :: EXEC-INT CreateTimelineEventInteractor
16:04:07.908 INF :: EXEC-INT ExecuteDatabaseQueryInteractor<Task<IEnumerable<TimelineEvent>>>
16:04:14.636 INF :: EXEC-DBQ UpdateExternalCalendarsQuery
16:04:17.122 ERR :: System.ComponentModel.Win32Exception (5): Отказано в доступе.
   at System.Diagnostics.NtProcessManager.GetModules(Int32 processId, Boolean firstModuleOnly)
   at Toggl.WPF.Extensions.WindowInfoUtils.GetWindowInfoFromHandle(IntPtr hWnd)
16:04:35.671 INF :: EXEC-INT FunctionInteractor<Task<Preferences>>

Пазл окончательно сошёлся:

  1. В Toggl Track была включена функция Record Timeline (запись шкалы времени активности). Эта функция отслеживает, в каких окнах и приложениях работает пользователь в течение дня.
  2. Когда мы переключаемся на окно TESO, Toggl Track через системный хук видит появление нового активного окна и вызывает метод WindowInfoUtils.GetWindowInfoFromHandle(hWnd), чтобы узнать путь к процессу и его модули.
  3. Метод обращается к WinAPI через NtProcessManager.GetModules().
  4. Но процесс eso64.exe защищён античитом! Windows закономерно возвращает системную ошибку Access Denied (Код ошибки 5: Отказано в доступе).
  5. При обработке этого исключения внутри цикла диспетчера WPF и фонового интерактора происходит обновление состояния интерфейса Toggl Track, из-за чего внутреннее скрытое окно HwndWrapper кратковременно перехватывает системный фокус ввода.

Почему из-за этого сворачивалась игра#

В Windows есть существенная разница между режимами отображения игр:

  • Эксклюзивный полноэкранный режим (Exclusive Fullscreen);
  • Полноэкранный в окне без рамки (Borderless Windowed / Windowed Fullscreen).

Открываем конфигурационный файл настроек TESO:

Documents\Elder Scrolls Online\live\UserSettings.txt

И находим строчки:

SET PreferExclusiveFullscreen "1"
SET FULLSCREEN "2"

Параметр PreferExclusiveFullscreen "1" принудительно заставляет игровой движок забирать эксклюзивный контроль над видеоадаптером. В таком режиме DirectX-приложение монопольно владеет экраном.

Как только любое стороннее приложение (даже невидимое окно размером 0×0 на долю секунды) получает статус Foreground Window, Windows считает, что пользователь покинул игру, и принудительно минимизирует окно эксклюзивного полноэкранного режима на панель задач.

Проверка теории#

Проверяем: завершаем процесс Toggl Track:

Stop-Process -Name TogglTrack -Force

Снова разворачиваем окно TESO и мониторим 15–20 секунд.

Результат: игра стабильно висит на переднем плане, фокус не теряется, никаких сворачиваний на рабочий стол нет!

Как решить проблему#

Есть два пути решения — со стороны Toggl Track и со стороны самой игры (а лучше применить оба).

1. Отключаем проблемную функцию в Toggl Track#

Если вы пользуетесь Toggl Track, но вам не критична автоматическая поминутная шкала открытых программ:

  1. В приложении Toggl Track откройте Preferences / Настройки.
  2. В разделе настроек найдите и отключите пункт Record Timeline (Запись шкалы времени).

После отключения этой функции Toggl Track перестаёт опрашивать дескрипторы модулей чужих защищённых процессов и больше никогда не перехватывает фокус.

2. Переключаем TESO в режим «В окне без рамки» (Borderless)#

Это универсальный рецепт не только для TESO, но и для большинства современных игр под Windows 10/11:

  1. В игре: Настройки → Видео → Режим экрана → Оконный (без рамки) (Windowed Fullscreen).
  2. Либо в файле Documents\Elder Scrolls Online\live\UserSettings.txt при выключенной игре выставить:
    SET PreferExclusiveFullscreen "0"
SET FULLSCREEN "2"

В режиме «Оконный без рамки»:

  • Картинка визуально абсолютно неотличима от полного экрана (занимает монитор целиком без рамок и заголовков);
  • Задержка ввода и FPS в Windows 10/11 благодаря современному Flip Model практически идентичны эксклюзивному режиму;
  • Главное: игра физически остаётся обычным окном рабочего стола. Даже если в фоне прилетит уведомление, выскочит апдейтер или сторонний софт чихнёт в фокус — игра никогда не свернётся на панель задач.

Выводы#

  1. Если полноэкранная игра циклично сворачивается через 3–5 секунд после разворачивания — почти наверняка фокус крадет какое-то невидимое окно.
  2. Не гадайте: простой 20-строчный PowerShell-скрипт с GetForegroundWindow ловит виновника мгновенно.
  3. Фоновые утилиты учёта времени (вроде Toggl) с функцией «Timeline tracking» могут спотыкаться об античит игр и ронять эксклюзивный полноэкранный режим.
  4. Эксклюзивный полноэкранный режим в современных играх — пережиток прошлого; Borderless Windowed бережёт нервы и избавляет от подобных сюрпризов.
