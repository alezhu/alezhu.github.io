Synthetic Gamepad с ошибкой (Код 28) в Диспетчере устройств Windows 10: что это и как исправить#

На днях открываю Диспетчер устройств (Device Manager) в Windows 10 и вижу там неопознанное устройство с жёлтым треугольником: Synthetic Gamepad. В свойствах красуется классическая ошибка:

Для этого устройства не установлены драйверы. (Код 28) Для элемента управления или набора разделов устройства не выбран драйвер.

При этом никакого нового геймпада я не подключал, а имеющиеся контроллеры работают как обычно. Первая естественная реакция — нажать «Удалить устройство». Удаляется. Но проходит немного времени (или перезагрузка) — и эта штука снова бодро висит в списке с тем же восклицательным знаком. Попытка нажать «Обновить драйвер» ожидаемо приводит к вердикту системы: «Система Windows не смогла найти драйверы для этого устройства».

Стало интересно раскопать, откуда растут ноги и почему Microsoft подсунула такое «счастье».

Откуда ноги растут: расследование#

Смотрим свойства устройства:

  • Имя: Synthetic Gamepad
  • ИД оборудования (Hardware ID): SYNTHETICGamepad
  • ИД экземпляра устройства (Device Instance Path): SWD\SYNTHETICGAMEPADENUM\SYNTHETICGAMEPAD0

Префикс SWD\ сразу намекает: перед нами Software Device (программно эмулируемое устройство). Значит, в системе работает какая-то служба или драйвер, который настойчиво создаёт эту виртуальную шину.

Лезем в журнал установки драйверов C:\Windows\inf\setupapi.dev.log и смотрим события по SYNTHETICGamepad. Находим интереснейшую картину:

  1. В начале ноября через Microsoft Store в фоновом режиме обновился пакет «Службы игр» (Microsoft Gaming Services) до версии 39.118.30001.0.
  2. В процессе установки этот пакет тихо накатил Windows Installer пакет XboxService.msi, который зарегистрировал службу XBOX Input Service (XboxService, исполняемый файл: C:\Program Files\XboxService\x64\XboxService.exe).
  3. При установке выполнилась команда:
    pnputil.exe /add-driver "C:\Program Files\XboxService\x64\SynthGpDriver\synthgpdriver.inf" /install
  4. Эта служба отвечает за XBOX Synthetic Gamepad Bus — виртуальную шину для эмуляции контроллеров Xbox, предназначенную для облачного гейминга (Xbox Cloud Gaming), режима виртуального мышиного курсора на портативных консолях вроде ROG Ally и расширений современного стека GameInput.
  5. Служба XboxService запускается в автозапуске и регистрирует в системе виртуальное устройство Synthetic Gamepad.

В чём же баг Microsoft?#

А вот тут самое забавное. Открываем установленный файл драйвера C:\Program Files\XboxService\x64\SynthGpDriver\synthgpdriver.inf (в хранилище драйверов Windows он прописался как один из oem*.inf) и читаем секцию совместимости:

[Manufacturer]
; This driver package is only installable on Win11+
%ManufacturerName% = Standard,NTamd64.10.0...22000 ; wudfrd.inf introduced in build 22000

[Standard.NTamd64.10.0...22000]
%DeviceName% = SynthGpDriver, SYNTHETICGAMEPAD
%SyntheticHidDeviceName%=Synthetic_Hid, HID\VID_045E&PID_0B09&IG_00

Смотрите на комментарий самих разработчиков Microsoft:

; This driver package is only installable on Win11+

Сборка 22000 — это релизная версия Windows 11! А на рабочей машине установлена Windows 10 (билд 19045).

То есть Microsoft:

  • Выпустила обновление Gaming Services и службу XboxService в том числе для пользователей Windows 10.
  • Служба XboxService запускается и честно создаёт устройство SYNTHETICGamepad.
  • Windows 10 пытается привязать к нему свежеустановленный драйвер synthgpdriver.inf.
  • Но SetupAPI видит требование NTamd64.10.0...22000, понимает, что текущая Windows 10 (19045) не подходит под фильтр сборки >= 22000, и выдаёт в лог:
    dvi: {Select Best Driver}
! dvi: Selecting driver failed(0xe0000228)
! dvi: Error 0xe0000228: There are no compatible drivers for this device.
  • Итог: устройство зависает в состоянии Код 28 (CM_PROB_FAILED_INSTALL). А так как служба XboxService крутится в фоне постоянно, простое удаление устройства из Диспетчера устройств не помогает — служба создаёт его заново при следующей проверке/загрузке.

Классическая несогласованность отделов в Редмонде: сервис накатили на все поддерживаемые винды, а драйвер ограничили только одиннадцатой.

Как исправить#

На работу реальных геймпадов (подключенных по проводу или Bluetooth) эта синтетическая шина никак не влияет — они работают через стандартные драйверы XInput/HID.

Поэтому самое простое и чистое решение — остановить и отключить службу XboxService и удалить висящее виртуальное устройство.

Запускаем PowerShell от имени Администратора и выполняем три строчки:

# Останавливаем службу эмуляции XBOX Input Service
Stop-Service XboxService -Force

# Отключаем автозапуск службы
Set-Service XboxService -StartupType Disabled

# Удаляем фантомное устройство из PnP
pnputil /remove-device "SWD\SYNTHETICGAMEPADENUM\SYNTHETICGAMEPAD0"

После этого:

  1. Ошибка мгновенно пропадает из Диспетчера устройств.
  2. При перезагрузке служба больше не стартует и виртуальный девайс заново не спавнится.

Если вдруг когда-то в будущем вам понадобится вернуть службу обратно:

Set-Service XboxService -StartupType Automatic
Start-Service XboxService

(хотя до тех пор, пока Microsoft не исправит секцию [Manufacturer] для Windows 10 в обновлениях Gaming Services, устройство вернется ровно с той же ошибкой Код 28).
