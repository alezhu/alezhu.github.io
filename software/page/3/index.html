Visual C# 2010 Express + MS SQL Server (Express)

Visual C# 2010 Express + MS SQL Server (Express) Столкнулся с особенностью Express версии Visual Studio 2010 (наверняка в ранних экпрессах тоже самое) - в качестве источника данных (Data Source) Visual C# Express предлагает на выбор только источники, работающие с файлом, а не с сервером. Вот так это выглядит: В то же время в Visual Web Developer 2010 Express ( и в VS2005 Pro тоже ) список выглядит так: Как видите, список побогаче. Вначале я решил было, что Visual C# переглючило, и стал искать возможность получить список источников данных, аналогичный тому, что есть в Web Developer. Переустановка ни к чему не привела. Тогда я нашел место, где в реестре хранится этот список для Visual WD Express - это тут HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\VWDExpress\10.0\DataSources. Я его скопировал в HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\VCSExpress\10.0\DataSources - для VC#Express. Но это ничего не дало. В ходе экспериментов выяснилось, что похоже список возможных источников данных зашит где-то в самом VC#Express. Откуда такие данные? Очень просто - допустим VC#Express берет все источники из реестра и как-то проверяет что это файловый источник, а не серверный. Тогда берем и перименовываем в реестре GUID одного из файловых источников - я менял {485C80D5-BC85-46db-9E6D-4238A0AD7B6B} на {485C80D5-BC85-46db-9E6D-4238A0AD7B6C}. Если бы наше допущение было верным - то количество источников не поменялось бы. Но это не так - Microsoft SQL Server Database File исчезает (это его GUID я менял) из списка. Также я пытался копировать ветку реестра с этим GUID - дубликат источника не появлялся. Кроме того, выяснилось что VC#Express не проверят файловый ли это источник. Как это проверить? Опять же просто - берем GUID серверного Microsoft SQL Server {067EA0D9-BA62-43f7-9106-34930C60C528} и меняем его на GUID Microsoft SQL Server Database File {485C80D5-BC85-46db-9E6D-4238A0AD7B6B} - и, о чудо!, в списке источников данных теперь вместо файлового источника - серверный: Но чуда на самом деле нет. При попытке выбрать этот источник - все равно появляется окно выбора файла с базой даннных: а не выбора сервера и базы данных на нем, как должно бы было быть: К сожалению, в недрах Visual C# 2010 Express мне не удалось найти место, где забита эта логика, так что я оставил попытки что-то тут изменить. Кому не лень копать - дерзайте =) Позже в интернете я нашел упоминания подобной проблемы у других людей, и оказалось, что это совсем не проблема, а такая “фича” всех компонентов Express версии. То есть типа хотите сервер - покупайте нормальную Visual Studio. Но есть одно но - “фича” не распространяется на Visual Web Developer 2010 Express - в нем то все нормально с подключением к серверам. И это как говорится “доставляет”. А почему - расскажу ниже. Итак, что у нас в результате. У нас есть VC#Express, на котором мы хотим писать Windows приложение, которое должно подключаться к MS SQL Server. Но есть проблемка - как Data Source невозможно выбрать MS SQ Server, а значит нельзя, например, перетаскивать таблицы в дизайнер того же Linq2SQL (с Entity Framework я думаю тоже самое). Что делать? Рекурсивный Application Data

Рекурсивный Application Data В Vista компания Microsoft “перекроила” ссылки на пользовательские данные. Если раньше все лежало в Documents and Settings, то теперь все не совсем так. Например, вместо Documents and Settings используется Users, а первый сделан как символическая ссылка на второй. А вот Documents and Settings\All Users лежит в ProgramData прямо в корне системного диска. При этом чтобы не нарушить работу старых приложений, которые про новую моду ничего не знают, сделана куча символических ссылок со старых “мест работы” на новые. И в частности есть рекурсивные ссылки, то есть такие ссылки, которые лежат внутри какого-либо каталога и ссылаются на него же. Далеко ходить не надо - ProgramData\Application Data ссылается на сам ProgramData. Таким образом, хотя, например, данные приложений Microsoft для всех пользователей лежат фактически в ProgramData\Microsoft\* старое приложение будет их искать по пути Documents & Settings\All users\Application Data\Microsoft\*. Но благодаря тому что, D&S ссылается на Users, а Users\All users ссылается на ProgramData, а ProgramData\Application Data ссылается на сам ProgramData - мы попадем туда где фактичеки данные и лежат. С такими ссылками возникает проблема при поиске. То есть приложение (например, Total Commander), которое что-то ищет в Users и его подпапках попадает на Application Data, не разбирает, что это ссылка ведущая как бы назад, и снова начинает в ней искать - хотя поиск там уже был. И в итоге получается мы залезаем в вот такие вот дебри: c:\Users\All Users\Application Data\Application Data\Application Data\Application Data\Application Data\Application Data\Application Data\Application Data\Application Data\Application Data\Application Data.… Как с этим бороться? Регистрация Visual Studio 2010 Express

Регистрация Visual Studio 2010 Express 12 апреля вышла финальная версия Visual Studio 2010. Одновременно с выходом “больших” версий были выпущены бесплатные версии в редакции Express. Версии бесплатные, но требуют ввода ключа, который можно получить на сайте Microsoft. Процесс расписан в картинках на самом сайте здесь http://www.microsoft.com/express/support/regins/ Я таким образом спокойно зарегистрировал VS2010 C# Express. Но как я узнал от @rwsh с какого-то момента работать это перестало. Действительно, попробовав зарегистрировать Visual Web Developer 2010 Express, я получил тот же самый результат - ключа не было. Но немного поэксперементировав я все же нашел решение. Заключается оно в следующем - когда вы заполняете анкету, необходимо поменять вывод страницы на английский язык. Для этого в строке браузера в самом конце адреса открытой страницы находите строку “&lcid=1049” - это если у вас русский язык. Далее меняете lcid на 1033 (то есть должно получиться “&lcid=1033”) и нажимаете Enter. Это приведет к перезагрузке страницы с анкетой, но уже на английском языке. После этого отправляете анкету, нажав внизу страницы кнопку “Продолжить”, и попадаете на страницу с благодарностями за регистрацию и ключом. ЗЫ. Никто не в курсе что удалить в реестре, чтобы эта регистрация пропала?

Skype не сворачивается в трей в Windows 7

Skype не сворачивается в трей в Windows 7 Не так давно разработчики Skype выпустили обновление своего продукта. Вернее было даже два обновления с небольшим перерывом. Версии первого я, к сожалению, не помню, а второе - 4.2.0155. Но началось все с первого. А началось следующее - в Windows 7 Skype при закрытии своего главного окна не убирал кнопку с панели задач. Причем в других версиях Windows - все работало как и раньше. Официальный форум на сайте Skype запестрел сообщениями об этом баге. На что разработчики ответили, что это не баг, а фича. Не знаю точно чем они руководствовались, но судя по всему такое поведение создано в угоду тому как Windows 7 по умолчанию показывает приложения на панели задач, а именно большими кнопками без подписей типа так: ![[bigbutton.png]] Таким образом, винда показывает, что приложение запущено, а по правой кнопке, например, можно менять свой статус в Skype - то есть некий аналог трея. Но многим, в том числе и мне, это похоже не нужно. Более того, я, например, панель задач в Windows 7 привожу в стандартному виду, типа так: ![[taskbar.png]] И мне эта кнопка маячащего в бэкграунде Skype’а, естественно нафиг не нужна. Так вот, поскольку разработчики не изъявили желания исправлять эту багофичу, народ стал искать пути решения. И нашел. Оказалось что, если поставить в свойствах Skype запускаться в режиме совместимости с Windows Vista или XP - то он начинает работать как и положено. Но тут разрабы выпускают новую версию и все - эта фишка с совместимостью перестает работать. Короче, мне это не понравилось и я наваял патч, который заставляет Skype версии 4.2.0.155 под Windows 7 при закрытии сворачиваться в трей (вернее убирать свою кнопку с панели задач - в трее он и так все время есть). ВНИМАНИЕ! Сразу хочу предупредить - в Skype встроена проверка на изменения его файла, поэтому в данном случае ее пришлось отключить, поскольку при пропатчивании файл меняется. Также никакого подробного тестирования не проводилось - вроде все работает, но кто знает что там могло сломаться. Поэтому никаких гарантий не даю и никаких претензий предъявлять не надо - все делаете на свой страх и риск. Качаете тут http://www.box.net/shared/ffdxhpax7v ZIP-файл, распаковываете его в папку со Skype, запускаете распакованный exe, тыкаете Apply patch. На выходе имеем пропатченный skype.exe и изначальный непатченный вариант в skype.bak. Если что пойдет не так - вторым перезапишите первый. UPDATE Для версии 4.2.0.158 - http://www.box.net/shared/ktqutbd7no Для версии 4.2.32.155 - http://www.box.net/shared/r5p23gskyd Для версии 4.2.32.158 - http://www.box.net/shared/33f0eyy0tl UPDATE 2 В версии 4.2.x.166 в настройках появилась соответствующая галочка. Патч больше не нужен. Обновляйте версию.
